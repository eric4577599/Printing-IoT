## 1. 系統架構與技術決策

### 1.1 核心架構 (Core Architecture)
本系統採用 **Clean Architecture** 與 **CQRS** (Command Query Responsibility Segregation) 概念，確保高擴充性與維護性。

*   **API層 (SmartParts.API)**: 負責接收 HTTP 請求，驗證 DTO，呼叫 Application Services。
*   **Application層**: 包含業務邏輯 (Business Logic)，定義 Use Cases (e.g., `CreatePartCommand`, `GetPartQuery`)。
*   **Domain層**: 定義 Entities, Value Objects, Domain Events (e.g., `PartCreatedEvent`).
*   **Infrastructure層**: 實作 Repository (EF Core), External Services (Email, IoT Sync).

### 1.2 資料庫策略 (Multi-Database Strategy)
*   **FlexoDB (IoT Core)**: `Users`, `Machines`, `Alarms` (Source of Truth).
*   **SmartPartsDB (New)**: `Parts`, `Suppliers`, `Inventory`, `MaintenanceTickets`.
*   **Sync Mechanism**: 
    *   **Users**: 唯讀同步 (Read-Only Sync) 或 Cross-Context Query。建議初期採用 **Cross-Context** (在同一 API 中注入兩個 DbContext) 讀取使用者權限。

## 2. 資料庫設計 (Database Schema Detail)

### 2.1 零件模組 (Parts Module)

#### Table: `Parts` (零件主檔)
| Column | Type | Nullable | Description |
|:---|:---|:---|:---|
| `Id` | UUID | PK | Primary Key |
| `InternalPN` | VARCHAR(50) | NO | 內部料號 (Unique Index) |
| `Name` | VARCHAR(100) | NO | 品名 |
| `Specification` | VARCHAR(255) | YES | 規格描述 |
| `Category` | VARCHAR(50) | YES | 分類 (e.g., 軸承, 電控) |
| `SafeStockLevel` | INT | NO | 安全庫存量 (Default: 0) |
| `Unit` | VARCHAR(20) | NO | 單位 (pcs, m, set) |
| `CreatedAt` | DATETIME | NO | 建檔時間 |
| `UpdatedAt` | DATETIME | YES | 更新時間 |

#### Table: `Suppliers` (供應商)
| Column | Type | Nullable | Description |
|:---|:---|:---|:---|
| `Id` | UUID | PK | Primary Key |
| `Name` | VARCHAR(100) | NO | 供應商名稱 |
| `ContactPerson` | VARCHAR(50) | YES | 聯絡人 |
| `Phone` | VARCHAR(20) | YES | 電話 |
| `Email` | VARCHAR(100) | YES | Email |

#### Table: `SupplierParts` (零件供應關聯 - 1對多)
| Column | Type | Nullable | Description |
|:---|:---|:---|:---|
| `Id` | UUID | PK | Primary Key |
| `PartId` | UUID | FK | 關聯 Parts.Id |
| `SupplierId` | UUID | FK | 關聯 Suppliers.Id |
| `ManufacturerPN` | VARCHAR(100) | YES | 原廠/供應商料號 |
| `Price` | DECIMAL(18,2) | YES | 單價 |
| `LeadTimeDays` | INT | YES | 交貨天數 |
| `IsPreferred` | BOOLEAN | NO | 是否為優先供應商 (Default: false) |

### 2.2 維護模組 (Maintenance Module) - Phase 2

#### Table: `MaintenanceTickets` (維修工單)
| Column | Type | Nullable | Description |
|:---|:---|:---|:---|
| `Id` | UUID | PK | Primary Key |
| `TicketNo` | VARCHAR(20) | NO | 工單號 (e.g., MT-20260122-001) |
| `MachineId` | UUID | NO | 關聯 FlexoDB.Machines (Logical FK) |
| `RequestorId` | UUID | NO | 申請人 (FlexoDB.Users) |
| `Status` | INT | NO | 0:Open, 1:In-Progress, 2:Closed |
| `Priority` | INT | NO | 0:Low, 1:Normal, 2:High, 3:Critical |
| `Description` | TEXT | NO | 故障描述 |
| `Solution` | TEXT | YES | 處理對策 |

## 3. API 接口定義 (API Design)

### 3.1 Authentication
*   **Header**: `Authorization: Bearer <JWT_FROM_IOT_LOGIN>`
*   **Validation**: Backend 驗證 JWT Signature (需共用 Secret Key)。

### 3.2 Parts API

#### `GET /api/v1/parts`
*   **Query Params**: `page=1`, `size=20`, `keyword=bearing`
*   **Response**:
    ```json
    {
        "data": [
            {
                "id": "uuid...",
                "internalPN": "Bearing-6200",
                "name": "深溝滾珠軸承",
                "safeStockLevel": 10,
                "currentStock": 5, // Calculated
                "preferredSupplier": "SKF Agent"
            }
        ],
        "total": 100
    }
    ```

#### `POST /api/v1/parts` (Create)
*   **Body**:
    ```json
    {
        "internalPN": "Motor-5HP",
        "name": "5HP AC Motor",
        "suppliers": [
            { "supplierId": "uuid...", "manufacturerPN": "M-500", "isPreferred": true }
        ]
    }
    ```

#### `GET /api/v1/parts/{id}` (Detail)
*   回傳包含完整 `SupplierParts` 列表的詳細資訊。

## 4. 前端架構 (Frontend Architecture)

### 4.1 專案結構 (Vite + React)
```
src/
├── api/
│   ├── axiosClient.js  (設定 BaseURL 與 Interceptors)
│   ├── partsApi.js     (Parts CRUD)
│   └── authApi.js      (Login/Fallback)
├── components/
│   ├── Layout/         (Sidebar, Header with User Info)
│   ├── UI/             (Shared UI Library: Button, Modal, Table)
│   └── Parts/          (PartForm, PartList, SupplierSelector)
├── pages/
│   ├── Parts/          (PartsManagementPage)
│   ├── Inventory/      (StockPage)
│   └── Maintenance/    (TicketPage)
├── context/
│   └── AuthContext.jsx (處理 Token 與 User State)
└── routes.jsx          (React Router 定義)
```

### 4.2 關鍵功能實作
1.  **Shared Authentication**:
    *   在 `AuthContext` 初始化時，檢查 `localStorage` (或是 Cookie) 是否存有來自 IoT Port 5600 寫入的 Token。
    *   *注意*: 由於 Port 不同，`localStorage` 無法直接跨 Port 讀取。
    *   **解決方案**: 使用 **SSO 跳轉** 或 **手動重新登入**。
    *   **推薦流程**: User 在 5600 點擊 "Smart Parts" -> 帶著 Token 跳轉到 5100 (`http://parts.local?token=xyz`) -> 5100 寫入自己的 Storage -> 清除 URL 參數。
