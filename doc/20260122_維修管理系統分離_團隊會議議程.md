# 團隊會議議程：維修管理系統分離規劃

**日期**：2026/01/22（待確認）  
**目標**：討論將維修管理模組從現有 IoT 系統完全分離為獨立程式的架構與執行計畫

---

## 會議議程

### 1. 策略確認 (10 min)
- **專案型態**：獨立程式 (Standalone Application)
- **部署位置**：同一台 Mac Mini，不同資料夾
- **資料庫**：暫時獨立，未來可合併
- **認證機制**：共用登入 (IoT 未開時 Fallback 獨立登入)

### 2. 架構設計審查 (15 min)
- 雙系統 Port 分配 (IoT: 5000/5173, MMS: 5100/5200)
- 共用認證 Token 驗證流程
- 故障/維護訊息雙向 API 對接設計

### 3. 待移轉模組確認 (10 min)
**Frontend (12+ 檔案)**
- `modules/maintenance/MaintenancePage.jsx`
- `components/maintenance/*` 全部元件
- `pages/MachineMaintenance.jsx`

**Backend**
- `MaintenanceController`
- `MaintenanceService`
- 相關 Entities 與 Migrations

### 4. 開發時程討論 (10 min)
| Phase | 內容 | 預估天數 |
|:---|:---|:---|
| 1 | 專案建立、共用認證 | 5 天 |
| 2 | 零件管理、批次匯出入 | 8 天 |
| 3 | 維護模組移轉 | 7 天 |
| 4 | API 整合測試 | 5 天 |

### 5. 待決事項 (15 min)
1. Port 分配確認
2. 資料庫名稱 (`maintenance_system`?)
3. 移轉順序 (零件優先 or 維修優先)
4. 共用認證 Fallback 策略
5. API 版本控制 (`/api/v1/`)

### 6. Action Items 分工
- Eric：建立新專案、設計共用認證
- 廠務：準備零件清單 Excel 範本
- 全員：確認本提案
