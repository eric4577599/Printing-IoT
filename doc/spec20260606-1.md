# 規格文件:MM 設備保養維修外掛程式(2026-06-06)

## 1. 定位

MM(Maintenance Management)是自 Printing IoT 主系統移出的**獨立外掛程式**:

- 主系統不再內建保養/維修功能
- 客戶有需求時,單獨部署 MM(可與主系統共用主機或完全獨立)
- 程式位置:`/Volumes/X10Pro/cusor pool/MM/`(非 Printing IoT repo 範圍)

## 2. 系統架構

```
┌─────────────────────────────┐      ┌──────────────────────────────┐
│ Printing IoT 主系統          │      │ MM 外掛程式(選配)            │
│  backend-api :5200          │      │  mms-backend :5300           │
│  frontend    :5600          │      │  frontend(待補)             │
│  FlexoDB(已無保養表)        │      │  MmsDB(postgres :5433)      │
└─────────────────────────────┘      └──────────────────────────────┘
        無相互依賴                      ERP ──POST /api/settings/erp-sync──▶
```

### 2.2 資料模型(MmsDB)

| 資料表 | 用途 | 備註 |
|---|---|---|
| MaintenanceSchedules | 保養排程 | 頻率 Daily/Weekly/Monthly/AdHoc |
| SpareParts | 備品零件 | 庫存量、最低庫存閾值 |
| MaintenanceRecords | 保養/維修紀錄 | FK→Schedule、FK→SparePart,建立時自動扣庫存 |
| MaintenanceSettings | ERP 級聯設定 | SettingSource: InheritErp / LocalOverride;EffectiveValue 依 Source 動態取值 |

### 2.3 API 端點(:5300)

| Method | Path | 說明 |
|---|---|---|
| GET/POST | /api/schedules | 保養排程 |
| GET/POST | /api/parts | 備品零件 |
| GET/POST | /api/records | 保養紀錄(自動扣庫存) |
| GET/POST/PUT/DELETE | /api/settings | 級聯設定 CRUD |
| POST | /api/settings/erp-sync | ERP 批量推送設定值 |

## 4. 部署規格

### 4.1 獨立部署(預設)

```bash
cd MM && docker compose up -d
# postgres :5433(避開主系統 :5432)+ mms-backend :5300
```

### 4.2 與主系統共用 postgres(選配)

修改 `MM/docker-compose.yml`,移除 postgres service,
`ConnectionStrings__DefaultConnection` 指向主系統 postgres,Database 仍用 `MmsDB`。

### 4.3 對外網域

`mms-api.ericchh.work`(Cloudflare Tunnel)— 原指向主系統 compose 內 `mms-backend:5300`,
**待 MM 獨立部署後需重新設定 tunnel 路由**。
