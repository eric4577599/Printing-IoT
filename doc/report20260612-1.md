# 任務報告 — PriIoT 現況確認:Docker 卡死復原 + sm-frontend restart policy 根因修復

> 日期:2026-06-12
> 分支:`feat/extract-maintenance`

## 背景

使用者要求確認 PriIoT(`priiot.ericchh.work`)現況。檢查發現對外站台全線 530(Cloudflare tunnel 斷線)。

## 診斷過程

1. **公網檢查**:`priiot` / `smartparts` / `mms-api` 全部回 530 → origin(本機 Docker stack)離線
2. **Docker 狀態**:daemon 回報 `Docker Desktop is unable to start`,backend process 在跑但 VM 引擎起不來
   - VM console.log 最後活動於本地 08:54,之後 backend 於 09:13 重啟並卡死(`_ping` 持續 503 超過 7 分鐘)
   - 判定:Docker Desktop VM 半死狀態(host backend 與 VM 脫鉤),非程式碼或 compose 問題
3. **完整重啟**:`quit app` + `pkill` 清掉殘留 process 後重新 `open -a Docker` → daemon 復活,全部 stack(36 容器)由 restart policy 自動拉起
4. **唯一例外**:`printingiot-sm-frontend-1` Exited(255)未被拉起 —— 與 2026-06-11 報告(report20260611-1)同樣症狀,**第二次發生**

## 根因(sm-frontend 反覆躺平)

`docker-compose.yml` 中 `sm-frontend` 服務**漏設 `restart:`**(實際 policy 為 `no`),其他 7 個服務皆為 `restart: always`。因此每次 Docker daemon 重啟,只有它不會自動復活。

## 修復內容

| 項目 | 動作 | 結果 |
|---|---|---|
| Docker Desktop | 完整關閉殘留 process 後重啟 | daemon 就緒,36 容器全部拉起 |
| sm-frontend restart policy | `docker-compose.yml` 補 `restart: always` | `docker compose up -d sm-frontend` 重建生效,inspect 確認 `RestartPolicy=always` |
