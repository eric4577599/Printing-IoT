### T2 失敗項(阻斷)

#### 【F-1】`DocsPortal.jsx` 以裸 `fetch()` 呼叫已上鎖端點,登入後 `/docs` 頁面必定壞掉

**檔案行號**:`frontend/src/pages/DocsPortal.jsx:60-73`

```js
  const fetchDocument = async (filePath) => {
    setLoading(true);
    setError(null);
    try {
      const response = await fetch(`/api/docs/${encodeURIComponent(filePath)}`);   // ← 第 64 行
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
```

**證據鏈**:

1. `backend/PrintingIoT.API/Controllers/DocsController.cs:17` 本輪新增 `[Authorize]`,
   `GET /api/docs/{filename}` 未帶權杖一律 401(`AuthorizationMatrixTests.cs:52` 也正是這樣斷言的)。
2. 全前端唯一掛 `Authorization` 標頭的地方是 `services/api.js:27-34` 的 axios 請求攔截器。
3. 掃描 `frontend/src` 全部 `.js` / `.jsx`(排除 `tests/`),**只有 `DocsPortal.jsx:64` 這一處**
   繞過 `api.js` 直接用瀏覽器原生 `fetch()`:
   ```
   $ grep -rn --include="*.js" --include="*.jsx" -e "fetch(" -e "axios" frontend/src | grep -v /tests/
   frontend/src/pages/DocsPortal.jsx:64:      const response = await fetch(`/api/docs/${...}`);
   frontend/src/services/api.js:1:import axios from 'axios';
   frontend/src/services/api.js:6:const api = axios.create({
   ```
   原生 `fetch` 不經過 axios 攔截器,因此**永遠不會帶 `Authorization` 標頭**。
4. 結果:使用者即使以 ADMIN 正常登入,點開 `/docs` 任何一份文件都會走進
   `DocsPortal.jsx:67` 的 `throw new Error('HTTP 401')`,畫面顯示
   `t('docs.error.loadFail'): HTTP 401`。**這不是「需要登入才能讀」,而是「登入了也讀不到」。**

**為何算規格不符(而非未涵蓋的 edge case)**:

- 規格 §8 E12 明寫:「`/api/docs` 需要登入 → 產品 UI 的 `/docs` 頁面**在登入後才能讀**。這是刻意收緊,不是缺陷。」
- 規格 §12 R8 同樣寫「不再**匿名**可讀」。
- 兩處都預設「登入後可讀」;實作給出的是「任何情況都不可讀」,**與規格描述的行為相反**。
- 規格 §5.2 的設計意圖是「所有 API 呼叫都經攔截器帶權杖」,`DocsPortal` 是唯一漏網的呼叫端。
  §10 的檔案清單沒有列到它,屬 RD 應在實作時發現的接線遺漏(規格用行為條款 E12 已把預期講死,不算歧義)。

**RD 修正方向(擇一,建議第 1 案)**:

1. 在 `frontend/src/services/api.js` 新增一支 `getDocument(filename)`,走既有 axios instance
   (自動帶權杖,並沿用 401/403 分流),`DocsPortal.jsx:64` 改呼叫它。
   注意回應是 Markdown 純文字,需設 `responseType: 'text'` 或直接取 `response.data`,
   且 `api` 的 baseURL 已含 `/api`,路徑應為 `/docs/${encodeURIComponent(filePath)}`。
2. 若堅持保留原生 `fetch`,必須自行 `headers: { Authorization: 'Bearer ' + getToken() }`
   —— 但這等於在 `authStorage` 之外多開一個取用點,與 §5.1「唯一允許碰認證儲存的地方」相衝突,不建議。

**同時補上的驗收測試(下一輪 DoD)**:

- 前端:新增案例斷言「取文件的請求走 axios instance,且帶 `Authorization` 標頭」
  (可比照 `frontend/src/tests/services/apiAuth.test.js` 的 mock instance 寫法)。
- 建議一併加一條「`frontend/src` 內不得出現裸 `fetch('/api...')`」的掃描測試,
  比照 `tests/security/noHardcodedCredentials.test.js`,防止同類旁路再度出現。

**RD 交付報告的落差**:`docs/report20260905-2.md` 第 86 / 145 行只把 `/docs` 列為
「需知會使用端的行為變更(R8)」,**沒有指出前端呼叫端未接權杖**。修好之後也請一併更新該報告。
