## 0. 三層分流(T1/T2/T3)定義與路由規則

| 層 | 意義 | 失敗時路由 |
|---|---|---|
| **T1** | 建置/型別/靜態層(build、lint、type、資產存在) | 失敗多屬實作細節 → **回 RD** |
| **T2** | 功能/邏輯層(單元、整合、行為符合 AC) | 邏輯錯 → **回 RD**;AC 本身矛盾/不可達 → **回 PM 修規格** |
| **T3** | 端對端/環境層(真網址、真硬體、真 Cluster、跨系統) | 環境未備 → **BLOCKED/待外部**;環境備而失敗 → 依因回 RD 或 PM |

**模擬判定圖例**:✅ 模擬 PASS｜⚠️ 模擬 PASS 但有前提｜⛔ BLOCKED(需外部資源)｜🔁 需回 RD｜📋 需回 PM。

### 6.1 關鍵結論
1. **沒有任何一項因「規格矛盾」需回 PM**——五項規格 AC 皆可達且無自相矛盾(與 C′ 遷移那次 AC-B5「0↔0」矛盾不同)。
2. **回 RD 的兩處**(S3 翻譯、S4 D1/D2)本質是「工作尚未做 / 待真機定參數」,非規格或既有實作錯誤;屬正常 backlog 推進。
3. **T3 全數 ⛔** 皆為**外部資源未備**(Eric 手動 / OT 硬體 / Cluster 環境),為各項天生依賴,已於規格 S*.5 明載,非工作流缺陷。
4. 本回合為紙上模擬;任一項解禁後,以對應 S 段 AC 為準補真測試並回填「實測」欄。

### 6.2 建議推進順序(依可獨立交付性)
1. **S3 越/泰文**(純資料,無外部依賴,可立即動工)
2. **S2 拖拉排序 Phase1**(函式庫已裝,前端獨立)
3. **S5 Redis 小改**(合併 multiplexer + 命名校正,可先做,不需 Cluster)
4. **S1 Cloudflare 301**(待 Eric 一次手動)
5. **S2 Phase2 / S4**(待 id-DTO 對齊 / OT 硬體)
