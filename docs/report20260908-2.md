# report20260908-2 · S14 文件不經 API + 角色分權(E5 通過)

> 2026-09-08 · Eric 登入後實機操作 `/docs` 時回報 404

## 1. E5 的實際結果:失敗,但不是 401

handoff 預期的風險是「後端一上鎖文件頁回 401」(S5 那次的舊傷)。
實際看到的是 **HTTP 404**,畫面還顯示「此功能將在 Phase 3 後端整合時完成」。

## 2. 根因:`doc/` 從來沒進過 API 容器

`DocsController` 本身是好的 —— 端點在、`[Authorize]` 在、路由對、防目錄遍歷也做了。
問題在**檔案不在那裡**:

- `docker-compose.yml` 的後端建置脈絡是 **`./backend`**
- `doc/` 在**專案根**,不在 `backend/` 底下
- 所以 `Dockerfile` 的 `COPY . .` **根本抄不到它**
- `GetDocPath()` 的三段 fallback(`../../doc`、`cwd/doc`、`../doc`)在容器裡全部落空
- `Directory.Exists` 為 false → 清單回空陣列、單檔一律 404

實查佐證:`docker exec printingiot-backend-api-1 ls /app` 底下**沒有 `doc/`**。

這與 S9 的 **O-06** 是同一個病灶的兩面:產品 UI 的文件頁描述著一個不存在的系統 ——
S9 說的是內容過期,這裡是**檔案根本不在**。

## 3. Eric 的裁決與代價

Eric 指示:**文件不需要 API,管理者要能全看,操作者看操作說明書。**

我先回報了前提有誤(API 不是問題),並把兩條路的差別攤開讓他選:

| | 好處 | 代價 |
|---|---|---|
| **打包進前端**(採用) | 永遠不會 404、不依賴後端、離線可看 | 文件成為靜態資源,**能載入前端的人不必登入就抄得到** |
| 修容器留 API | 文件仍受後端登入保護 | 依賴後端活著,部署時多一個必須跟著走的目錄 |

Eric 選打包。`doc/` 裡有業務推廣企劃書、會議議程、部署指南,
**這個外洩面是已知並接受的取捨,不是疏漏** —— 已寫進 `docRegistry` 檔頭。

## 4. 改了什麼

### 4.1 `docRegistry.js`(新增)

`import.meta.glob('../../../../doc/*.md', { query: '?raw' })` —— 建置時收檔,**不用 eager**。

三條紀律:

1. **清單由實際存在的檔案產生,不是手寫的。** 原本 31 個 md 檔只有 18 個被手寫索引列到,
   其餘(業務推廣企劃書、高中生簡報、ERROR_TEST_MATRIX 等)在畫面上等於不存在。
   改由 glob 產生後,新增一個 md 檔就自動出現。未被歸類的落到「其他」分類,**不會消失**。
2. **延遲載入。** 31 檔約 178 KB,全部塞進主 bundle 只為了看其中一份並不划算。
   每份文件是自己的 chunk,點了才抓 —— 實測主 bundle 970 KB → 974 KB。
3. **角色分權在這裡收斂**,不散在畫面上。`loadDoc()` 是取得內容的唯一入口,
   在那裡再擋一次,而不是只靠側欄不畫出來。

角色規則:

| 角色 | 看得到 |
|---|---|
| ADMIN / ENGINEER / SUPERVISOR | 全部 |
| OPERATOR | `操作說明書.md` + `Operator Manual.md` |
| 無角色 / 未登入 | 無 —— 預設拒絕,與後端同一立場 |

**中英兩版都給 OPERATOR 是我加的判斷**:現場有五個語系,只給中文那版
等於對非中文母語的作業員關門。若判斷有誤,改 `OPERATOR_FILES` 一行即可。

### 4.2 Docker:前端建置脈絡改為專案根

**前端原本也是 `context: ./frontend`,會踩到與後端一模一樣的坑** —— `doc/` 進不去。

改為 `context: .` + `dockerfile: frontend/Dockerfile`,並在 Dockerfile 內
**刻意重建「`doc/` 與 `frontend/` 並列」的結構**(`/src/doc` 與 `/src/frontend`),
讓 `'../../../../doc/*.md'` 在容器內與開發機解析到同一個地方。
兩邊路徑不同構就會變成「本機過、進 Docker 炸」,那正是本專案已知的坑之一。

脈絡變大,`.dockerignore` 補上 `.git` / `node_modules` / `backend/**/bin` /
`docs` / `.credentials-*.txt` / `.env`。

### 4.3 一條安全測試換掉判準,而不是放寬

`noBareApiFetch.test.js` 原本釘「DocsPortal 必須 import `getDocument`」。
那是 S5 當下的正確**代理指標** —— 要防的是裸 fetch 不帶權杖而固定回 401。
S14 之後 DocsPortal **完全不發網路請求**,判準的前提消失。

沒有放寬斷言,換成兩條對準真實不變量的:
① DocsPortal 不得有任何 `fetch(` / `XMLHttpRequest`,且不得 import `services/api`;
② 內容只能從 `docRegistry` 取得。
(同 `[[test-assertions-must-match-real-invariants]]`)
