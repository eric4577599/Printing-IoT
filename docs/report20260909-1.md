# report20260909-1 · S15 定時寫入間隔改以秒為單位

> 2026-09-09 · Eric 於設定頁回報「數據記錄設定以秒」

## 1. 現況與問題

畫面顯示「定時寫入間隔:`0` **分鐘**   目前: 0 分鐘 (6 秒)」。

底層**本來就是秒** —— `dataLogInterval` / `data_log_interval` 都是秒,
只有輸入欄被換算成分鐘(`Math.floor(秒 / 60)`)。造成兩個實際問題:

1. **實際生效的 6 秒顯示成「0 分鐘」**,看起來像沒設定。
2. **低於一分鐘的值根本打不進去** —— 輸入是分鐘、乘 60 才送出,
   所以現場想設 6 秒、30 秒都做不到,而那正是這台機器目前在用的值。

## 2. 後端的判準(改之前必須先知道)

`SignalMappingProvider.cs:162`:

```
if (double.IsNaN(seconds) || seconds <= 0 || seconds > MaxDataLogIntervalSeconds)
    return DefaultDataLogIntervalSeconds;   // 300
```

**`<= 0` 或 `> 3600` 會被靜默換成 300 秒。** 原本的分鐘輸入打 0 就會送出 0,
後端默默改成 300 —— 畫面說 0、機器跑 300,而且沒有任何地方會顯示這件事。

## 3. 改了什麼

### 3.1 輸入改秒

`min=1 max=3600 step=1`,顯示「目前: N 秒」;N ≥ 60 時附上「(M 分 S 秒)」,
未滿一分鐘不顯示「0 分 6 秒」這種贅述。

### 3.2 前端判準與後端對齊,而且說出來

超出 1–3600 或非整數時 **不送出**,並顯示紅字:
「需為 1-3600 之間的整數秒。超出範圍不會送出 —— 送出去也只會被後端換成預設的 300 秒。」

**擋下來比放行好** —— 放行的話使用者以為設定生效了,實際跑的是 300。
離開欄位時把草稿還原成目前生效值,不留下假的顯示。

### 3.3 打字中途不再送出(改秒才浮現的問題)

原本 `onChange` 每按一鍵就寫 localStorage + 打 API。分鐘時代典型值是一位數,
影響有限;**改秒之後典型值是三位數,打「300」的過程會先把 3 秒送到後端與 Worker** ——
那會讓機器真的用 3 秒的頻率寫資料庫一小段時間。

改為草稿狀態,**離開欄位或按 Enter 才送出**;值沒變就不打 API。

### 3.4 判準抽成獨立模組

`utils/dataLogInterval.js`(`parseLogInterval` / `describeSeconds` / 三個常數)。
一開始寫在元件檔裡,`react-refresh/only-export-components` 立刻多兩個 lint error ——
那個規則是對的:這些是純規則不是元件,獨立出來也才好測。

### 3.5 i18n

`noteItem3` 由「建議設定:3-10 分鐘」改為「180-600 秒(3-10 分鐘)」;
新增 `noteItem4`(有效範圍)與 `intervalOutOfRange`(警語),五語系齊補。
