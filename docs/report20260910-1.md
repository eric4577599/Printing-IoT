## 1. 交付

### 1.1 主系統(Printing-IoT)

- 通訊設定新增 **`mm_base_url`**(後端預設空字串、前端輸入欄、payload 一併送出)。
- 導覽列新增 **「🔧 維護」外連**,開新分頁,帶 `?machine=<machine_id>&from=priiot`。
- 顯示條件兩個都要成立:**網址設得出合法連結** 且 **角色為 ADMIN / ENGINEER / SUPERVISOR**
  (OPERATOR 看不到,與 S14 文件分權同一組判準)。未設定網址時整個不渲染 ——
  不留一個必然打不開的死連結。
- 判準抽成 `utils/mmLink.js`(`buildMmUrl` / `shouldShowMmEntry` / `MM_ENTRY_ROLES`)。
- MainLayout 在 localStorage 沒有設定時**向後端要一次** —— 否則從沒開過設定頁的終端
  永遠看不到入口;取不到就不顯示,不打擾使用者。
- `target="_blank"` 一律配 `rel="noopener noreferrer"`。

### 1.2 MM

- 新增 `src/machineBinding.js`:讀網址意圖、在台帳解析、記住/解除、依綁定過濾。
- 進站時**只有帶了 `machine` 參數才打 API** —— 單獨開 MM 完全不多送任何請求(AC-01)。
- 綁到 → 頂部藍色標示「已綁定機台 M20」+ 解除按鈕;
  綁不到 → 橘色標示說明代號不在台帳中,**畫面照常可用**(AC-03)。
- 綁定存 **sessionStorage**,不存 localStorage —— 一台終端多人輪用不該互相繼承。

## 2. 順手根治一個現行的資料遺失 bug

抽 payload 的過程中發現:`CommunicationTab` 有**四處各自手寫**同一份 payload,
而且**四處遺漏的欄位還不一樣**:

| 位置 | 少了什麼 |
|---|---|
| 定時寫入間隔 | `mqtt_broker_url` / `mqtt_topic` / `machine_id` |
| PLC 欄位變更 | `machine_id` |
| 機台識別碼 | `mqtt_broker_url` / `mqtt_topic` |
| **「儲存」按鈕** | **`plc_monitor_interval`** 與兩個 `mqtt_*` |

後端 `UpdateCommunicationSettingsAsync` 是**整包覆寫** Redis 字串 —— 送什麼存什麼,
沒送的鍵**直接消失**。所以**按一次「儲存」就會把監控頻率與 MQTT 設定洗掉**。

「修正 #9」在 2026 年稍早修過其中一處,但沒有拿掉成因(同一份 payload 手寫四次),於是復發。
本輪收斂成 `utils/commPayload.js` 的單一函式:**新增欄位只會有一個地方要改**。
測試釘住欄位集合與那三個曾被漏掉的欄位。

> 這不是本輪要做的事,但我正要往這堆手寫 payload 裡加**第五個**欄位。
> 不先收斂,等於自己再種一次同樣的坑。
