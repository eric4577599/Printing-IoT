### 2.1 建立 ERP 金鑰(**等 ERP 真的要串接時再做**)

本趟只建管道,沒有要立刻串接。`ApiKeys` 套用後是空表,**系統一切正常** ——
只是 ERP 推單不可用,與這一趟之前的狀況相同,不影響任何頁面或其他端點。

真的要串的那天,由 ADMIN 帶自己的 JWT 呼叫:

```bash
# 1) 取得 ADMIN 權杖
TOKEN=$(curl -s -X POST http://<host>:5200/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"<admin>","password":"<password>"}' | jq -r .token)

# 2) 建立金鑰 —— 回應中的 plainKey 只出現這一次,立刻交給 ERP 端設定
curl -s -X POST http://<host>:5200/api/v1/apikeys \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"客戶 ERP 推單","expiresAt":null}'
```

ERP 端只需要在推單請求加一個標頭:

```
POST /api/erp/push-orders
X-Api-Key: pio_xxxxxxxxxxxx_xxxxxxxx...
```

輪替時:先建新金鑰 → ERP 換設定 → 觀察舊金鑰的 `lastUsedAt` 不再前進 → 再撤銷舊的
(`POST /api/v1/apikeys/{id}/revoke`)。**撤銷不刪列**,稽核軌跡留著。

### 2.2 刷新憑證效期

`Auth:RefreshTokenHours` 預設 12(涵蓋一個班)。要改就設環境變數 `Auth__RefreshTokenHours`。

**注意**:migration 套用後,**既有的登入階段沒有刷新憑證**,仍會在 2 小時後被登出一次;
下一次登入起才享有刷新。

## 4. 驗收擋下的東西

### 4.1 base64url 的底線讓約三分之一的金鑰從產生當下就是死的

`ApiKeyGenerator.ExtractPrefix` 原本用 `plainKey.Split('_')` 並要求剛好三段。
但祕密段是 base64url,**`_` 正是它用來取代 `/` 的字元** ——
只要亂數產生的祕密段含底線就會切出四段以上,前綴解析回 `null`,金鑰一律 401。

這是隨機出現的,單跑一次測試有機會全綠。抓到它靠的是兩個測試同時紅:
一個是端到端推單失敗,一個是「建立回應的 plainKey 解析不出前綴」。

修法是 `Split('_', 3)`(限制段數,第三段保留餘下的底線),並補兩條回歸:
祕密段含底線時仍解析得出前綴、**連續產生 200 支金鑰每一支都解析得出前綴**。

教訓:亂數產生的憑證,格式解析必須用「產生器實際產出的樣本」測,
不能只拿手寫的漂亮字面值測 —— 手寫的那些永遠不含底線。

### 4.2 安全測試本身擋住了正當的修改

`noHardcodedCredentials.test.js` 的判準之一是「GeneralTab 不得出現 `password:`」。
名冊接後端之後,建立帳號**必須**把密碼送給 `POST /v1/auth/users`,這條判準會把正當修改一併擋掉。

沒有放寬,而是換成兩條更精確、更貼近真正不變量的:
- 任何一行只要碰 `localStorage` 就不得同時碰密碼(註解行不算);
- 名冊快取的白名單投影 `toRosterCache` 不得有 password 欄位。

原本的粗判準是「密碼不落地」的代理指標;代理指標與真實意圖分歧時,換掉代理指標,不要放寬。

### 4.3 jest-dom 沒掛進 setupFiles

`vitest.config.js` 的 `setupFiles` 是空陣列,`@testing-library/jest-dom` 雖然在
`package.json` 裡但從未註冊,`toBeDisabled()` 之類的斷言全部不可用。
本趟改用原生屬性判斷(`el.disabled`),與專案其他測試一致,不動設定。

| 項目 | 說明 |
|---|---|
| **存取權杖無法撤銷** | JWT 無狀態。登出或停用後,已發出的存取權杖最長仍有 2 小時殘命。要收掉需黑名單或改不透明權杖 |

| 密碼自助變更 / 忘記密碼 | 未排,仍由 ADMIN 代改 |
| 多分頁登出同步 | 不做跨分頁廣播(S6 起的刻意取捨,E8) |
