# B19 車速送不到前端 — 修復報告(2026-11-13)

## 根因
`MonitorController.GetRealtimeData` 用預設的 `JsonSerializer.Deserialize<MonitorData>`(**區分大小寫**)讀 Redis `factory/monitor`,
但 Worker(`TelemetryPipeline`)以 **camelCase** 寫入。`MonitorData` 只有 `DI1` 帶 `[JsonPropertyName("di1")]`,所以只有計數對得上;
`deviceId` / `speed` / `status` / `timestamp` / `source` 全部落回預設值(null / 0 / 0001-01-01)。與 `report20260927-1.md` §3.2 的症狀逐項吻合。
推翻了該報告「API 從別的來源組資料」的猜測 —— 資料來源沒錯,是反序列化漏欄位。

## 修正
`MonitorController.cs`:新增 `SnapshotOptions = new(JsonSerializerDefaults.Web)`(不分大小寫 + camelCase),讀取時帶入。
`MonitorData` 與 Worker 都沒動。

## 驗證
| 項目 | 結果 |
|---|---|
| 新測試 `MonitorControllerTests`(以 Worker 實際的 camelCase 序列化資料餵控制器) | 修前**失敗**(`deviceId` 為 null),修後通過 |
| `dotnet test` 全體 | **362 通過 / 0 失敗**(基準 353) |
| 真實情境 | 只重建 `backend-api`(`--no-deps`),以 OP1 登入看板,Redis `speed: 50` → 畫面車速 **50**(修前恆為 0) |
