## 1. 前置:現場沒有訊號,自己造

驗收當下查到的事實:`ProductionLogs` **0 筆**、`ProductionCompletions` **0 筆**、Redis `factory/monitor` **空的** ——
**沒有任何真實 PLC 資料在流**,而完工需要「生產數量 > 0」。

兩條路:

1. 開 `模擬生產` —— 但那個工具列是 `canDebug`(ADMIN / ENGINEER)才渲染,OPERATOR 看不到。
2. **直接往 MQTT broker 發訊號** —— 取這條。

```bash
docker exec printingiot-mqtt-broker-1 mosquitto_pub -h localhost -p 1883 \
  -t factory/machine/update -m '{"deviceId":"SIMULATOR","speed":0,"length":10100,"status":0}'
```

Worker 收下 → 寫 `ProductionLogs` → 更新 Redis `factory/monitor` → 前端每秒輪詢 `/api/v1/monitor/realtime` 取到。
**這條路徑本身就是一次端到端驗證**(MQTT → Worker → Redis → API → 前端)。

⚠ 副作用已查證過才動手:`DeviceLockManager` 會把鎖指向 `SIMULATOR`,但那是**軟鎖** ——
規則 5 寫明硬體 ID(12 碼無連字號)出現時**立即接管**,所以不會擋住現場真機。
本次共注入 7 則訊號,`ProductionLogs` 因此多 7 筆。

## 3. 過程中發現的三件事

### 3.1 完工流程上有兩個 `alert()` 會凍結整個分頁

兩次撞到,兩次都必須關掉分頁才能恢復(瀏覽器擴充功能完全失去回應):

| 位置 | 條件 |
|---|---|
| `Dashboard.jsx:301`(`handleFinish`) | 生產數量為 0 時按 F4 |
| `FinishOrderModal.jsx:114` | 欠量 > 門檻(預設 50)且未填欠量原因 |

對真人只是多點一下,但**任何自動化(含未來的 e2e 測試)碰到就直接卡死**。
S17 已經把登入失敗的 alert 換成畫面訊息,完工這兩個是同一類、尚未處理 → 建議列 backlog。

### 3.2 回填會把「有 defectQty 但沒有不良明細」的舊紀錄靜默算成 0 不良

`backfillMapper.js:225` 刻意不送 `defectQty`,由後端從 `defects` 明細重算(設計如此,註解也寫明)。
但 `useBackfill.js:77` 的差異偵測比的是「**送出去的明細加總**」與後端結果 —— 兩邊都是 0,於是**一致**,不會示警。

結果:舊紀錄若 `defectQty: 100` 而 `defects: []`,回填後不良數變 0、良率變 100%,而「有損轉換」清單**不會提到這件事**。

誠實標註:本次是**我造的測試資料**踩到的。現行版本寫出來的紀錄都帶 `defects` 陣列(實際紀錄已確認),
所以**是否真的存在這種舊資料尚未證實**。若要處理,判準應改成「拿紀錄自己的 `defectQty` 欄位對照」。

### 3.3 完工實績的 `DeviceId` 是空的

兩筆實績的 `DeviceId` 都是空字串。設定頁有「機台識別碼」欄位,推測是本機未設定。
影響:多台機器的實績分不出來源。建議現場上線前把機台識別碼填上。
