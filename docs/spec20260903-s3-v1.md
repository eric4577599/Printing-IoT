## 0. 名詞與縮寫

| 名詞 | 定義 |
|---|---|
| 完工實績(Completion) | 一張工單完工時產生的一筆生產結果紀錄:良品/不良品、時間、停機明細、OEE |
| 工廠日(ProductionDate) | 以工廠時區與工廠日界切分的生產日期,大夜班跨 00:00 仍算前一日 |
| 日界(DayBoundaryHour) | 工廠日的起點小時(0–23),例如 8 表示每日 08:00 換日 |
| 負荷時間(LoadTime) | 計算稼動率的分母,= 運轉時間 + 停機時間 − 準備時間 |

### 1.3 報表公式(GAP-05)

- `Dashboard.jsx` L285–L289:
  ```js
  const availability = totalTime > 0 ? jobRunTime / totalTime : 1;       // totalTime = run + stop
  const performance  = finishedOrder.qty > 0 ? Math.min(1, currentCount / finishedOrder.qty) : 1;
  const oeeCalc      = Math.round(availability * performance * 100);      // 缺良率因子
  ```
  `currentCount` 是計數器累計值(**含不良品**),分母為零時以 `1` 當滿分。
- `utils/reportUtils.js`:
  - `calculateUtilization(runTime, stopTime)` 分母 = `runTime + stopTime`,**沒有處理準備時間**;
  - `calculateDailySummary` 的 `avgOEE: average(records, 'oee')` 是**算術平均**,10 張小單會把 1 張大單稀釋掉。
- `hooks/useProductionTimer.js`:`prepTimeSeconds` 在「未達連續生產」期間每秒累加,而同一秒**也會**依車速計入 `jobRunTime` 或 `jobStopTime` —— 亦即 **準備時間與運轉/停機時間重疊**,這是分母要扣掉它的原因。

### 1.4 完工日界

`Dashboard.jsx` L309:`date: new Date().toISOString().split('T')[0]` —— `toISOString()` 是 UTC。台北時間 00:00–08:00(UTC 前一日 16:00–00:00)完工的大夜班工單,`date` 會落在**前一個 UTC 日**,與現場認知的工廠日不一致。

## 2. 設計原則

1. **後端是實績的權威來源**:完工實績以 HTTP 端點同步落地,回應帶回後端計算的 OEE 與工廠日;localStorage 降級為離線快取,不再是唯一真相。
2. **公式只有一份定義,兩處實作**:本輪報表仍讀 localStorage,故 C#(`OeeCalculator`)與 JS(`reportUtils`)必須依**同一份規則表(§5.1)**實作,並各自有測試釘住相同的邊界案例。前端那份在報表改讀後端後即可退場(§8 backlog)。
3. **不知道就說不知道**:任何因子的分母為零一律回 `0`,不得以 `1` 假裝滿分(沿用 S2 原則)。
4. **降級不中斷現場**:原因主檔 API 失敗或回空清單時,彈窗退回內建預設清單,現場照常能選原因。
5. **不加相依套件**:後端只用既有 xUnit / Moq / EF Core InMemory / `Mvc.Testing`;前端只用既有 vitest / axios / zustand。
6. **加法式變更**:只新增資料表與欄位,不改既有欄位型別、不刪既有資料。

**邏輯**:

1. 驗證(見 §6 驗證表);任一項失敗 → `400`,本體 `{ "success": false, "error": "<正體中文訊息>" }`,**不落地任何列**。

5. 回 `201 Created`(新落地)/ `200 OK`(冪等命中)。

## 5. 計算規則(唯一規格,C# 與 JS 皆依此實作)

### 5.1 規則表

設 `R` = 運轉時間、`S` = 停機時間、`P` = 準備時間(單位皆為分)、`G` = 良品數、`D` = 不良品數、`T` = 目標數量。

| # | 名目 | 公式 | 分母為零 / 例外 |
|---|---|---|---|
| 1 | 負荷時間 `L` | `L = max(0, R + S − P)` | — |
| 2 | 稼動率 Availability | `A = min(R, L) / L × 100` | `L ≤ 0` → `0`。`min` 的理由:準備時間與運轉/停機重疊(§1.3),沒有明細可拆,以 `L` 夾住上限確保不超過 100% |
| 3 | 效能 Performance | `Pf = min(G / T, 1) × 100` | `T ≤ 0` → `0`。**分子用良品數**(不含不良品),超產以 100% 封頂 |
| 4 | 良率 Quality | `Q = G / (G + D) × 100` | `G + D ≤ 0` → `0` |
| 5 | OEE | `OEE = A × Pf × Q / 10000`(三者皆為百分比 → 除以 10000 回到百分比) | 任一因子為 0 → OEE 為 0 |
| 6 | 日報表平均 OEE | `Σ(oeeᵢ × qtyᵢ) / Σ(qtyᵢ)`,`qtyᵢ = goodQtyᵢ + defectQtyᵢ` | `Σqty ≤ 0` → `0`(**不得**退回算術平均) |

- 所有輸出四捨五入到**小數 1 位**(JS:`Math.round(x * 10) / 10`;C#:`Math.Round(x, 1, MidpointRounding.AwayFromZero)`)。
- 負數輸入(不該發生,但要防呆):時間類負值先夾到 `0`,數量類負值先夾到 `0`,再套公式。

> **設計註記(需在程式註解中保留)**:規則 3 依客戶要求以良品數當分子,與規則 4 的良率因子在數學上有部分重疊(良品被計入兩次),會使 OEE 略為保守。這是客戶明確指定的口徑,不是實作疏漏;若日後改回「總產出/目標」需同步改兩處實作與測試。

### 5.2 工廠日規則

`ProductionDate = (完工時間換算工廠時區後的當地日期) − (當地小時 < 日界 ? 1 天 : 0 天)`

| 完工時間(UTC) | 台北當地時間 | 日界 8 | ProductionDate |
|---|---|---|---|
| 2026-09-03T16:41Z | 2026-09-04 00:41 | 8 | **2026-09-03** |
| 2026-09-03T23:59Z | 2026-09-04 07:59 | 8 | **2026-09-03** |
| 2026-09-04T00:00Z | 2026-09-04 08:00 | 8 | **2026-09-04** |
| 2026-09-04T05:00Z | 2026-09-04 13:00 | 8 | 2026-09-04 |
| 2026-09-03T16:41Z | 2026-09-04 00:41 | 0 | 2026-09-04(日界 0 等同不調整) |

## 8. 已知 edge case 與預期行為

| 情境 | 預期行為 |
|---|---|
| 完工時後端不可用(斷網 / API 500) | 完工流程照常走完:localStorage 有紀錄、MQTT 照發、工單照樣換下一張;本地紀錄標 `syncState: 'pending'`,不 alert、不阻擋現場 |

| `defects` 全為 0 | 落地 `DefectQty = 0`,Quality = 100(若 G > 0),明細列仍照實寫入(0 也是資訊) |
| `stops` 為空但 `stopTimeMinutes > 0` | 照實落地:`StopCount = 0`、停機時間仍計入稼動率分母。不推測、不補假明細 |

| 大夜班 00:00–08:00 完工 | `ProductionDate` 為前一日(§5.2);報表當日彙總因此涵蓋完整班別 |
| 日界設為 0 | 等同「當地日曆日」,不做任何調整 |
| 工廠時區 id 在容器內不存在(缺 tzdata) | 退回 UTC+08:00 並記 warning,**不得**退回 UTC(AC-16) |

2. 沙箱外 `dotnet test backend/PrintingIoT.sln` 全綠,且**測試總數 = 本輪開工前實測基準 + 本輪新增數**(開工前先自行跑一次記下基準,不要沿用規格內的數字)。
3. `cd frontend && npm run test` 除既有豁免的 `frontend/tests/dashboard.e2e.test.js` 外全綠(其餘 12 個測試檔),測試總數同樣需閉合。
4. AC-01 ~ AC-30 逐條有對應且可證偽的測試並通過;沒有測試的驗收標準視為未完成。
5. `GET /swagger/v1/swagger.json` 仍可解析(既有 `OpenApiContractTests` 通過),新端點出現在 `paths` 內。
6. 交付報告寫入 `docs/report{YYYYMMDD}-{序號}.md`,必須明列:
   - §9 的 backlog 逐項(特別是「報表頁仍讀 localStorage」這一條,不可含糊);
   - 本輪對 OEE 口徑的變更會讓歷史數字與新數字不可直接比較(舊紀錄的 `oee` 欄位是舊公式算的),需提醒客戶;
   - 新增的 `Factory:TimeZone` / `Factory:DayBoundaryHour` 兩個設定項與其預設值。
