## S1. Cloudflare 301 轉址(`smartparts.ericchh.work` → `mms.ericchh.work`)

### S1.1 需求

### S1.2 現況(grounding)

- Repo 內無 Cloudflare API 憑證(`docs/report20260707-1.md:150`)→ **儀表板步驟只能由 Eric 手動執行**。
- `frontend/nginx.conf:1-18` 僅 SPA `try_files` + `/api/` 反代,**無任何 `return 301`/`rewrite`** → 轉址不應放 nginx/app,應放 **Cloudflare(Redirect Rule 或 Bulk Redirects)**。
- Tunnel ID:`60b8d51b-7f5e-4a21-9994-c0833f1ae62f`(`handoff.md:28`;報告內為 `<tunnel-id>` 佔位)。容器名 `printingiot-cloudflared-1`。

### S1.3 規格條文
1. 轉址機制放 **Cloudflare `ericchh.work` zone → Rules → Redirect Rules**。
2. 規則:
   - When incoming requests match:**Hostname equals `smartparts.ericchh.work`**
   - Then:**Dynamic redirect**,運算式 `concat("https://mms.ericchh.work", http.request.uri.path)`
   - Status code:**301**,勾選 **Preserve query string**
3. 前置條件:`smartparts` 的 DNS CNAME 記錄須**保留且為 Proxied(橘雲)** — 301 規則只在 Cloudflare proxy 有攔到請求時才會觸發。若先前刪 hostname 連帶刪了 CNAME,須補建 `smartparts` CNAME → `60b8d51b-7f5e-4a21-9994-c0833f1ae62f.cfargotunnel.com`(Proxied)。

### S4.1 需求

### S4.2 現況(grounding)
- Worker:`backend/PrintingIoT.Worker/Worker.cs`,`MqttWorker:BackgroundService`。兩條路徑:

  - **模擬器/PLC**:topic 寫死 `factory/machine/update`(`L62,118`);payload 多別名 `speed|line_speed`、`length|total_length|d1`、`status|status_code`(`L164-183`);**額外寫 Postgres `ProductionLog`**(`L189-211`)。`ProcessMachineUpdate` `L164-212`。
  - **關鍵不對稱**:WISE 路徑只吃單一 `di1` 計數並**自行算速度**、**不寫 ProductionLog**;模擬器路徑收預算好的 `speed` 且寫 log。
- 速度換算 `SpeedCalculator.cs`:`LastCount` 哨兵 `-1`(`L17`);**重置偵測** `currentRaw < LastCount`(`L42-48`,假設計數只會向下重置)→ 真機 **counter rollover/wrap 或接點彈跳**會被誤判為重置;取樣門檻 `timeDiff>0.008`(~0.5s,`L59`)、EMA `alpha=0.1`(`L68`)、`<1.0→0` 速度地板(`L72`)、硬上限 `_maxSpeedCache` 預設 `350`(`L25,64-65,73`)—— 這些平滑常數是對模擬器 ~10Hz 乾淨輸出調的,**未對真機接點抖動調校**。
- 裝置仲裁 `DeviceLockManager.cs`:真/模擬僅以 `IsHardwareId`(`id.Length==12 && !id.Contains("-")`,`L24`)heuristic 區分;硬體鎖定後永久拒軟體(`L48-51`);30s/10s 逾時(`L56,74`)。
- 現有訊號測試 `tests/mqtt_signal_test.py`:走**模擬器路徑**(`factory/machine/update`、`d1`,QoS1,broker `localhost:1884`),量測 **loss rate + latency**,無 `assert`;**未觸及真機 `Advantech/+/data`/`di1` 路徑**。WISE 訂閱無設 QoS(預設 QoS0,`L93`)。
- 前端模擬訊號源 `frontend/src/hooks/useSimulation.js`(依 speedFactor 生 `{d1,di1,line_speed}`,`L67,77-84`);`SimulationController.cs` 的 `/speed` 為 stub、速度命令下行**未實作**(`L47-59`)。假設「每100米一脈衝」(`mqtt_signal_test.py:112`)未經真機驗證。

### S4.3 規格條文(驗證計畫,非程式)
1. **現場資料擷取**:接一台實體 WISE 模組,訂閱 `Advantech/+/data`,原始側錄 N≥30 分鐘 `di1` 序列(含開機、加速、穩定、停機、換單各階段),存為基準資料集。
2. **比對項目**(真機 vs 模擬器假設):
   - `di1` 是否單調遞增?是否有 rollover(達位數上限歸零)?→ 驗證 `SpeedCalculator` 重置偵測 `L42-48` 是否誤判。
   - 接點彈跳:單次通過是否產生多個 edge?→ 是否需 debounce;現無。
   - 取樣率:真機發佈頻率 vs 模擬器 10Hz;`timeDiff>0.008` 門檻是否適用。
   - 脈衝/長度換算比:真機「每 X 米一脈衝」實測值 vs 假設 100 米。
   - deviceId 格式:真機 `parts[1]` 是否符合 `Length==12 && 無 '-'` 的 `IsHardwareId` heuristic。
   - QoS:真機是否需 QoS1 保證不丟(現 WISE 訂閱 QoS0)。
   - ProductionLog:WISE 路徑不寫 log 是否為預期?若真機也需生產履歷,列缺口。
3. **產出**:落差清單 + 每項「模擬器假設 vs 真機實測 vs 建議調整(常數/debounce/QoS/換算比)」。本回合以**模擬走查**先列出預期落差(見 RD 段),真機到位後再實測回填。
4. **不改 code**:凡需改 `SpeedCalculator`/`DeviceLockManager`/QoS 者,列為後續獨立需求,附建議值。

## S5. Redis 單機 → Cluster 擴充

### S5.1 需求
為未來擴充至 10+ 產線預作準備:評估把單機 Redis 升為 Cluster 的相容性與工作量,產出遷移計畫。（`doc/PROJECT_STATUS.md` §4 建議項。）

### S5.2 現況(grounding)— 關鍵:程式面幾乎 cluster-safe
- 函式庫 **StackExchange.Redis**,`IConnectionMultiplexer` singleton:`API/Program.cs:74-75`、`Worker/Program.cs:15-16`(`Connect(cfg["Redis:ConnectionString"] ?? "localhost:6379")`);Worker 另在 `Worker.cs:47` 再連一條(與 DI singleton 重複)。
- 用途**只有字串快取**,無 pub/sub、無 counter、無 transaction。使用鍵:
  - `factory/monitor`(即時快照,寫 `Worker.cs:160,202`;讀 `MonitorController.cs:30`)
  - `config/communication`(讀 `Worker.cs:65`、`SpeedCalculator.cs:95`;讀寫 `SettingsService.cs:26,49`)
  - `config/box-types`(讀寫 `SettingsService.cs:56,67`),常數 `SettingsService.cs:14-15`
- 即時推送給前端走 **MQTT**(`factory/monitor/update`,`Worker.cs:214-225`),**非 Redis pub/sub**。
- **無** multi-key op、`MULTI/EXEC`、`CreateBatch`、`KEYS/SCAN`、Lua、SortedSet/List → 每次都是單鍵 `StringGet/StringSet`,**本質 cluster-safe**。
- 殘留風險:鍵名用 `/` 無 hash tag(不同 slot,現無跨鍵原子操作故 OK,未來若跨鍵交易需 `{}` hash tag);Worker 兩條 multiplexer(Cluster client 更重,宜併一條);連線為單機 `Connect(host:port)` 無 cluster 旗標(`Program.cs:75`/`Worker.cs:47`)。
- 設定:`docker-compose.yml:67-71`(`redis:7-alpine`,單機,`6380:6369`... 實為 `6380:6379`);env `Redis__ConnectionString=redis:6379`(`L28,45`)。**命名歧異**:`.env.example:16-17` 曝 `REDIS_CONNECTION_STRING`,但 .NET binder 讀的是 `Redis:ConnectionString`/`Redis__ConnectionString` → `.env.example` 那個變數其實沒被直接讀。

### S5.3 規格條文(遷移計畫)
1. **結論先行**:應用程式碼幾乎**免改**;主要工作是**連線設定 + 基礎設施拓樸**,非邏輯。
2. 遷移步驟:
   - 建 Redis Cluster(最小 3 主 3 從,或托管服務);連線字串改為多節點端點清單。
   - StackExchange.Redis 以 cluster 模式連線(提供多 endpoint;函式庫自動處理 MOVED/ASK 重導向與拓樸)。
   - **合併 Worker 兩條 multiplexer 為一條**(`Worker.cs:47` 改用 DI singleton),降低 Cluster 連線負擔。
   - 校正設定命名歧異:統一 `Redis__ConnectionString`,清掉 `.env.example` 誤導的 `REDIS_CONNECTION_STRING` 或改為一致。
3. **防未來踩雷約定**:若日後需要跨 `config/*` 或 `factory/*` 多鍵原子操作,鍵名須加 hash tag(如 `config/{cfg}/communication`)使同 slot;現階段先於文件立此約定,不改鍵名。
4. 相容驗證:遷移後跑既有即時監控/設定讀寫/速度計算流程,確認三個鍵讀寫正常。
5. 本回合**不建 Cluster、不改 code**,僅產出計畫與相容性結論。
