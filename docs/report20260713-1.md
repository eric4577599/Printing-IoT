## S1. Cloudflare 301 — 執行手冊(無程式)

本項無 code。RD 交付為**可照做的儀表板手冊**與**驗證腳本**。

### S1.1 儀表板操作(Eric 手動)
1. Zero Trust → Networks → Tunnels → 選 MM 對應 tunnel → Public Hostname → 確認 `mms.ericchh.work` → `HTTP` → `mms-frontend:80`(handoff 已上線,確認即可)。
2. `ericchh.work` → DNS → 確認 `smartparts` CNAME 存在且 **Proxied(橘雲)**;若缺,補 `smartparts` CNAME → `60b8d51b-7f5e-4a21-9994-c0833f1ae62f.cfargotunnel.com`(Proxied)。
3. `ericchh.work` → Rules → Redirect Rules → Create:
   - Match:`Hostname equals smartparts.ericchh.work`
   - Then:Dynamic redirect,`concat("https://mms.ericchh.work", http.request.uri.path)`,**301**,Preserve query string ✓
   - Deploy。

### S1.2 驗證腳本【示意，未落地】
```bash
# 驗證 301 與路徑/查詢字串保留
curl -sI "https://smartparts.ericchh.work/parts?x=1" | grep -Ei "^(HTTP|location)"
#   期望:HTTP/2 301  +  location: https://mms.ericchh.work/parts?x=1
curl -sI https://mms.ericchh.work | head -1        # 期望 200 或登入 30x
dig @1.1.1.1 smartparts.ericchh.work +short        # 期望 Cloudflare IP(記錄仍在)
```

### S1.3 模擬邏輯走查
- 請求 `smartparts.ericchh.work/parts?x=1` → Cloudflare edge 攔截(因 Proxied)→ 命中 Redirect Rule(hostname 相符)→ 回 301,`location=https://mms.ericchh.work/parts?x=1` → 瀏覽器換址並重打 `mms` → tunnel → `mms-frontend:80` → 200。
- **失敗分支**:若 CNAME 被刪 → edge 無記錄可攔 → DNS 解析失敗/NXDOMAIN,301 規則永不觸發(這是最可能的坑,對應 AC-S1-4)。

### S2.2 模擬程式邏輯【示意，未落地】

`moveOrder` 由相鄰交換改為通用搬移(保留 index 0 鎖定):
```js
// MainLayout.jsx L182-187 示意改法【未落地】
function moveOrder(fromIndex, toIndex) {
  if (fromIndex === 0 || toIndex === 0) return;      // 執行中訂單鎖定(沿用 Schedule.jsx L45-48 商規)
  setOrders(prev => {
    const next = [...prev];
    const [moved] = next.splice(fromIndex, 1);        // 取出來源
    next.splice(toIndex, 0, moved);                   // 插入目標
    return next;                                       // useEffect(L162-163)自動寫 localStorage
  });
}
```

Schedule.jsx 表格包 DnD:
```jsx
// Schedule.jsx L193-231 示意改法【未落地】
<DndContext sensors={sensors} collisionDetection={closestCenter} onDragEnd={onDragEnd}>
  <SortableContext items={orders.map(o => o.id)} strategy={verticalListSortingStrategy}>
    <tbody>
      {orders.map((order, index) => (
        <SortableRow key={order.id} id={order.id}
                     disabled={index === 0}          // 執行中列不可拖
                     order={order} index={index}
                     selected={order.id === selectedScheduleId} />
      ))}
    </tbody>
  </SortableContext>
</DndContext>

function onDragEnd({ active, over }) {
  if (!over || active.id === over.id) return;
  const oldIndex = orders.findIndex(o => o.id === active.id);
  const newIndex = orders.findIndex(o => o.id === over.id);
  if (oldIndex === 0 || newIndex === 0) return;       // 再次守衛 index 0
  moveOrder(oldIndex, newIndex);                       // 前端狀態
  reorderOrders();                                     // 重編 seqNo 10,20,30...(MainLayout L247-253)
  // Phase2 選配:api.reorderOrders(orders.map(o => o.backendGuid)) → POST /api/orders/reorder
}
```

### S4.2 速度計算模擬走查(`SpeedCalculator` 現況邏輯)【示意】
```
輸入:currentRaw = di1(累積計數), now
若 LastCount == -1:            記錄基準,回 0            # L17 哨兵
若 currentRaw < LastCount:     判定「重置」,回 0        # L42-48 ← 真機 rollover 會誤入此支
delta = currentRaw - LastCount
若 timeDiff <= 0.008:          取樣過密,略過            # L59 (~0.5s 門檻,對 10Hz 模擬器)
rawSpeed = delta / timeDiff * 換算比                     # 假設每100米一脈衝
emaSpeed = 0.1*rawSpeed + 0.9*lastEma                    # L68 EMA alpha=0.1
若 emaSpeed < 1.0:             回 0                       # L72 地板
回 min(emaSpeed, maxSpeed(=350))                          # L64-65,73 硬上限
```

### S4.3 預判落差清單(真機 vs 模擬器假設)
| # | 面向 | 模擬器假設 | 真機潛在差異 | 影響 | 建議(待實測定值) |
|---|---|---|---|---|---|
| D1 | 計數重置 | 只會向下重置 | rollover/wrap 到位數上限歸零 | 誤判重置→速度歸零跳動 | rollover 感知:`delta = (cur - last + MOD) % MOD` |
| D2 | 接點彈跳 | 乾淨 edge | 單次通過多 edge | 速度虛高、長度多算 | 加 debounce / 最小間隔過濾 |
| D3 | 取樣率 | 10Hz | 真機發佈頻率未知 | `0.008` 門檻可能過濾真資料或不足 | 依實測頻率調門檻 |
| D4 | 脈衝換算 | 每100米一脈衝 | 真機接線比未知 | 速度/長度整體偏差 | 現場量測米/脈衝實值 |
| D5 | deviceId | `Length==12 && 無'-'` | 真機 id 格式未知 | 誤判軟/硬體、鎖定錯亂 | 確認真機 `parts[1]` 格式 |
| D6 | QoS | 訂閱 QoS0(`L93`) | 弱網丟訊 | 計數漏 → 速度低估 | WISE 訂閱改 QoS1 |
| D7 | ProductionLog | WISE 路徑不寫 log(`L189-211` 只在模擬器) | 真機也需生產履歷? | 真機跑無履歷 | 若需要,WISE 路徑補寫 log |
