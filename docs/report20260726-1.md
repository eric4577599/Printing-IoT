## 1. 目標

排程列表原以「上移 / 下移 / 重排」按鈕調整順序,改為**滑鼠直接拖拉列**重新排序,並保留商規:第一列(執行中訂單,index 0)鎖定不可移動、也不可被插到其前。保留鍵盤可操作性與既有按鈕。

## 3. 關鍵設計決策

1. **核心邏輯抽為純函式**:`resolveDragReorder(orders, activeId, overId)` 回傳 `{ allowed, oldIndex, newIndex }`,集中承載商規(找不到 id、來源=目標、來源或目標為 index 0 皆 `allowed=false`)。UI 只負責把 dnd-kit 事件餵進去,邏輯可脫離瀏覽器單元測試。

2. **`moveOrder` 改 splice 對既有呼叫零影響**:全專案 `moveOrder` 呼叫端(`Schedule`、`MaintenancePage`、`Dashboard` 的上/下移)皆為**相鄰**索引;相鄰的 splice 搬移與交換結果**完全相同**,故安全取代,額外獲得任意 from→to 能力。已由測試「相鄰搬移結果與交換相同」鎖住此不變式。

3. **點選 vs 拖拉不衝突**:`PointerSensor` 設 `activationConstraint.distance = 5`,位移未達 5px 視為點擊(觸發選取),超過才進入拖拉。

4. **執行中訂單鎖定雙保險**:`SortableOrderRow` 對 index 0 設 `useSortable({ disabled: true })` 且不掛 listener;`resolveDragReorder` 再擋一次(來源或目標為 0 皆忽略)。

5. **拖放後重新編號**:`handleDragEnd` 先 `moveOrder(oldIndex, newIndex)` 再 `reorderOrders()`,顯示序號重編為 10,20,30…(AC-S2-4)。兩者皆為 React functional `setOrders` 更新,依序套用於最新狀態。

6. **持久化沿用既有機制**:`orders` 變動由 MainLayout 既有 `useEffect` 寫入 localStorage,重整後維持新順序(AC-S2-3),本次無需另加。
