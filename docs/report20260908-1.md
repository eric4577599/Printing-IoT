## 3. S12:名冊編輯列的位置與可用性

Eric 回報「代碼 / 班別 / 操作員放錯位置,且需可以新增 / 刪除」。

### 3.1 根因

`LoginModal.module.css` 的 `.windowContainer` 是**固定 `width: 640px`**,
而 `.infoBar` 是 `display: flex` 且**沒有 `flex-wrap`**。infoBar 內有六個欄位
(當前班別 / 帳號 / 密碼 / 操作員 / 代碼 / Default),flex 項目不會縮到內容以下,
於是最後兩欄**溢位到卡片外面的灰底上**。

這不只是難看:**代碼欄實質上點不到,而 `handleAddUser` 要求代碼與操作員都有值** ——
所以「新增」永遠按不動。Eric 說的「需可以新增/刪除」其實是這個溢位造成的。

更根本的是語意混雜:**帳號 / 密碼是登入憑證,代碼 / 班別 / 操作員是下方名冊表的編輯欄**,
兩組不同性質的東西被塞進同一條 bar。

### 3.2 改法

- **編輯列獨立成一行**,依表頭順序(代碼 / 班別 / 操作員)擺在名冊表**正上方**,
  右側留出 `sideButtons` 的 80px + 12px gap,讓欄位與表格欄位對得上。
- **`.infoBar` 補上 `flex-wrap: wrap`**。即使現在只剩三欄放得下,仍保留 ——
  日後再加一欄要換行,而不是再溢位一次。
- **「Default」改為「班別」**,用既有的 `login.col.shift` 鍵,與表頭一致
  (原本是寫死的英文,也是 i18n backlog 的一筆)。
- **按鈕加停用狀態**:代碼或操作員未填時「新增」停用、未選取列時「刪除」停用。
  原本要按下去才跳 alert,現在條件不足是看得見的。
- **加一行說明**(五語系齊補 `login.hint.rosterLocal`):名冊是這台機器的觸控快捷清單,
  **新增或刪除名冊列不會建立或停用後端帳號**。這是現場最容易誤會的一點 ——
  帳號真相在後端,由管理者在設定頁維護(S7 G2)。

**刻意沒改**:名冊的 localStorage-only 性質、`handleUserRowClick` 只填帳號不填密碼、
`handleAddUser` 的 upsert 與 `username` 取代碼(S6 不變量)—— 全部維持原樣。
