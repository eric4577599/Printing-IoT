> 2026-11-05 · 承 `report20260927-1.md` §3.1

## 結論

✅ B18 已修。`Worker.cs` 斷線後會真的重連並重新訂閱,不再永久失聰。

## 改了什麼

| 位置 | 原本 | 現在 |
|---|---|---|
| `Worker.cs` `ExecuteAsync` | 偵測到斷線只印「Reconnecting」,什麼都沒做 | 呼叫 `ConnectAsync` + `SubscribeAllAsync`,失敗以指數退避重試(2s 起倍增,上限 60s) |
| 訂閱邏輯 | 寫死在 `StartAsync` | 抽成 `SubscribeAllAsync`,重連後重跑(clean session 訂閱不會保留;topic 每次重讀 Redis 設定) |
| 健康可見性 | 無 | 連線中但 10 分鐘沒收到任何訊息 → 印一次警告(失聰可被看見) |
| 退避計算 | — | 純函式 `MqttWorker.NextBackoff`,有單元測試 |

- `dotnet test`:353 → **360** 全過(新增 `MqttWorkerReconnectTests` 7 案例:0/1/2/3/5 次、截頂 60s、極大次數不溢位)。
- **真實情境**:重建 Worker 容器 → `docker compose restart mqtt-broker` 模擬斷線 →
  日誌出現 `disconnected. Reconnecting...` → `reconnected and resubscribed.` →
